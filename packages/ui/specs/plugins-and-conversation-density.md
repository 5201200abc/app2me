# 插件入口与会话密度

## 产品规则

1. 侧栏入口及插件主页标题使用“插件”；“市场源”等来源管理术语保持明确。
2. MyCode 官方插件目录由随应用打包的插件提供，不连接 z.ai CDN；旧官方远端来源及其失败状态在初始化时迁移为本地来源。个人来源仍按其原始地址刷新，失败时保留已安装插件和上次有效缓存，并显示来源故障。
3. 顶栏刷新更新个人来源，并从本地清单刷新官方目录；新增、安装、更新和卸载仍走原插件服务。来源地址不可用时不能把另一个产品的目录改名后当作官方目录。
   `node-repl-host` 是 Browser Use／Computer Use 的内部运行时宿主，不进入公开插件列表或已安装条。
4. Git 状态卡片使用更紧凑的字号、行高与宽度；变更审阅、分支切换、提交或推送仍可点击。回答开始时自动展开，展开后保持展开；卡片右上角不显示模式菜单或收起按钮。
5. 展开状态下的问答和输入框与左侧栏保留清晰间距，同时与右侧卡片不重叠；窄视口仍能阅读和输入。
6. 思考强度浮层进一步收紧宽度、留白和滑杆尺寸，原始 Host 档位、键盘操作与重置行为不变。
7. 首次启动不再显示职业与工作助手偏好两步引导，设置页不再提供该引导的入口；独立的会话迁移弹窗仍可按用户请求打开。

## 状态所有者与失败语义

```text
打包官方/个人来源 → Agent 持久化目录与刷新结果 → IPluginManagementService
                                             → pluginManagementStore 投影
                                             → 插件页、来源对话框

回答开始/手动展开 → SessionPane 布局模式 → ConversationTimeline 与状态卡片共用让位规则
```

- Agent 是市场目录和刷新失败的唯一事实所有者；UI 不另存一份来源健康状态。
- 个人来源刷新失败保留上次有效目录。错误提示来自已有 store 与 marketplace refreshFailure；手动重试走现有 `updateMarketplace`。官方本地目录无远程刷新失败状态。
- 布局和浮层仅改变呈现，不改变 Git、模型、思考强度或插件操作协议。

## 验收场景

1. 打开侧栏“插件”：页面标题同名；已安装条、公开和个人分段可用。
2. 离线打开插件页：官方内置插件出现，且不会请求 z.ai；既有官方远端失败状态被清除。个人来源失败时仍保留已安装/缓存插件，并可手动重试。
   `node-repl-host` 不出现在可见插件条目中。
3. 在 1280px 桌面宽度展开 Git 卡片：消息和输入框与左侧栏有明显间距，卡片与正文不重叠；缩到手机宽度后仍可完整操作。
4. 卡片右上角无三个点和双箭头；回答结束后保持展开，Git 卡片各操作仍可点击。思考浮层的滑杆、切换和重置可以用指针与键盘操作，Esc 后焦点恢复。
